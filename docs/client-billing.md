# Publishing a Stripe invoice to the client cabinet

1. Connect the Stripe account under admin integration settings. The API key needs permission to read invoices. Configure a Stripe snapshot webhook for invoice.updated, invoice.paid, invoice.payment_succeeded, invoice.voided and invoice.marked_uncollectible on the API endpoint `/api/stripe/invoice-events`. Set its signing secret in `STRIPE_INVOICE_WEBHOOK_SECRET`. Use the same Stripe account and test/live mode for the key, invoices and events.
2. Finalize the USD invoice in Stripe. Its total must equal the Vestov invoice. Set invoice metadata `vestov_client_id` to the numeric Vestov company ID, or use the company’s unique billing email as the Stripe customer email. Metadata takes precedence. A shared billing address is rejected unless metadata identifies the company. Optional metadata `vestov_invoice_id` must also match the local invoice if supplied. Stripe controls invoice emails; publish to the cabinet and email delivery are separate actions.
3. Open the corresponding invoice in the Vestov admin invoice list. Enter its Stripe invoice ID and select **Publish to client**. An existing local draft becomes issued and visible. Publishing does not create a second invoice, send mail, or charge a card.
4. On **Overview** and **Invoices**, amounts paid include settled manual invoices and Stripe’s recorded payments (including partial payments). Outstanding uses the remaining invoice balance. These are gross invoice payments, not bank deposits or a net-of-refunds statement. Signed events refresh linked records; **Refresh from Stripe** in the admin invoice details also reconciles a missed event. An unrelated Stripe invoice is not imported automatically.
5. **Open Stripe invoice** looks up a fresh hosted URL after checking the signed-in user’s access to the company. If the Stripe connection is unavailable, the saved billing history remains visible. Correct discrepancies in Stripe for linked invoices; the Hub prevents manual edits to their financial state.
